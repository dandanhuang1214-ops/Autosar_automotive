# P26：从配置缺口到有证据的变更影响

本轮平台实现验收与个人学习验收分开记录。先在合成工程中操作，再独立解释：

1. 找到应用 prototype 的 TYPE-TREF、事件和 runnable 的共同 internal behavior，再定位 RTE mapping 的 OsTask。说明哪些关系是直接读取，哪些检查仍未进行。
2. 把 TaskA 绑定改为 TaskB；核对两侧 source 和 dependency_edges，解释为什么这不会自动证明任务周期正确。
3. 只改 ComSignal 的位宽；检查为何命中一个 Tx 路径，且没有把另一个 Rx 路径或无关任务标成影响。
4. 加一条历史 ERROR 日志：观察当前结构结论是否保持，并说明为什么精确对象关联仍不是当前错误或根因证据。
5. 制造未知 XML 修改或重复身份；说明 partial 与 not-comparable 的区别，以及为什么“无已知影响”不是“肯定无影响”。
6. 移走两份源工程和原审查，只留下比较包，在另一个目录复验，再分别篡改来源、HTML、结论，记录拒绝结果。

独立操作日期、耗时、失败恢复与未理解项由真实操作者填写。未操作前不标记掌握；不得把本地合成回归表述为商业工具生成或实车经验。

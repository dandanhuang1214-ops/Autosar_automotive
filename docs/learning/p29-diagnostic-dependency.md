# P29：配置条件与独立诊断证据

本练习区分三个事实：配置策略通过；本次独立进程诊断通过；配置实际生成了被运行的代码。前两个可以由当前工作流分别核对，第三个需要生成来源，不能从前两个推断。

1. 执行公开离线项目，解释为何 project=blocked 而 verification=passed：后者验证保存结果的完整性，不表示 ECU 已运行。
2. 改变受保护 ComBitSize，确认诊断没有进程/运行目录；找到策略及静态拒绝来源。
3. 改变声明 DID，区别身份无法映射的 unassessed 与执行时收到负响应的 failed。
4. 对 configuration-semantic 声明解释缺少什么证据，不能根据相似名称补造映射。
5. 环境具备后实际运行固定 OpenBSW 构建；在记录中找出 ECU/client PID、通道锁、请求/响应、清理、本次标识和构建哈希。
6. 搬移证据并复验，再尝试用上次执行目录替换本次结果；解释完整性、上下文绑定与身份认证的区别。

完成情况由操作者实际记录，不把代理执行或 CI 成功当作本人独立掌握。

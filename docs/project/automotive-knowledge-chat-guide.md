## 启动与操作

```bash
PYTHONPATH=src .venv/bin/python -m automotive_workbench.knowledge_chat_server \
  --data output/knowledge-chat --port 8767 \
  --ollama-url http://127.0.0.1:11434 --model qwen3.5:2b
```

安装 wheel 后也可使用 `workbench-chat`。浏览器打开 `http://127.0.0.1:8767/`。顶部在“工程问答 / 项目验收 / 资料管理”之间切换；左侧直接列出最近会话，提供新会话、当前工程报告和图谱版本。问答视图把工作台证据与 Ollama 草稿分开呈现。点击任一历史工作台回答下的“查看这条回答的证据”，证据检查器才会展开，当前选中回答以蓝色边线标示；检查器按“工程 / 图谱 / 来源 / 核实”页签查看依据。窄屏用顶部“工作区”按钮打开会话与项目面板，证据检查器也按需打开，均可关闭或按 Escape 退出。服务只监听回环地址，写操作要求本次页面令牌，检查 Host，拒绝跨站 JSON 请求。数据保存在指定 `--data` 目录；它可能含私有工程问题、项目事实、图谱原文和模型原始响应，应使用仓库忽略的本地目录，不进入公开提交。

1. 在站点下载页首的 `graph.json`，并从实体详情下载两份来源 Markdown：`source-week07.md` 和 `source-did-rte-runtime.md`。在网页一次选择这三个文件，填写供人识别的站点版本标记，点击“导入并核验”。版本标记是用户输入的标签，**内容身份由 SHA-256 决定**，不能据此声称自动认证了站点发布身份。
2. 新版站点发布后重复导出和导入。Workbench 保存旧快照，显示节点、关系、结论、片段及核实工作单的新增/删除/变化；历史会话绑定当时图谱 SHA，打开旧回答时提示重新核对。Schema 或结论状态超出受支持的 `1.0` 候选契约时拒绝导入，等待明确版本化适配。
3. 若已在站点“待核实工作单”中填写结果，另行导出“知识核实记录 JSON”，在工作台单独导入。导入时记录当前图谱哈希，只作为**用户注释**显示，不改变图谱节点、关系或结论的候选状态。站点导出本身不含图谱哈希，使用者需确认所选记录对应当前图谱；换图谱版本后会提示记录过期。
4. 选择本机 `bundle/project-report.json` 路径后提问。每次调用现有 `build_request` 重放项目包，输出确定性状态、字段和值；图谱检索只给候选节点与关系、原来源文件链接。没有报告时只做候选图谱探索。项目静态 `passed` 不证明 CFG 生成、CAN 运行或实体 ECU。
5. 勾选 Ollama 且本轮有匹配的工程事实或图谱候选时，网页才会请求本地模型生成独立的“未经语义审阅草稿”；请求、原始响应、模型 digest、token 用量和输入快照写入本地 `runs/`。有草稿时网页先显示草稿，确定性证据摘要可展开查看。模型不可用、截断或身份漂移时仍显示证据摘要，并在回答内及顶部状态明确说明没有可用模型回答；没有匹配证据时明确说明本轮未调用模型。`model_requested`、`model_attempted` 和 `model_skip_reason` 是兼容旧字段的附加状态，供历史会话区分“未启用”“未调用”和“调用失败”。模型草稿不能自动成为工程事实或知识图谱核实结果。
6. “保存记忆”只记录用户明确输入的偏好或决定；通用记忆和按项目报告 SHA 绑定的记忆分开，可编辑、删除。聊天历史保存在本地 SQLite；模型回答与旧项目状态不自动提炼为长期记忆。

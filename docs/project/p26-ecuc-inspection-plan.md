# P26 真实 ECUC 配置体检与跨层定位

更新：2026-10-01。当前主实现阶段 implementing。用户提供本地配置工程并要求先分析再决定升级方向，随后授权继续升级；据此新增本阶段。P25 安装交付已远端通过，人工演示与真实外部反馈仍待验收，未标记整阶段完成，也不将代理分析等同真实用户使用反馈。

## 用户能力与实施顺序

目标是从真实工程中回答“实际选用了哪些配置，引用是否可定位，哪些集成关系还没有记录，改动将影响哪里”。新消费者独立版本化，旧 P22 SWC ARXML 子集继续保持原范围。

1. **项目感知的只读体检**：DPA 声明文件 + ECUC value collection 决定活动模块，保存来源快照、hash 和 XML/对象定位；识别选定模块缺失、重复选择、路径歧义、选定范围断引用和 RTE 任务未绑定；合成正负例、迁移/篡改复验和本轮七 job 验收。
2. **通信跨层定位**：按真实 VALUE-REF 连接 Com → EcuC/PduR → CanIf → Can，支持收发方向和信号/组信号，不以名称猜测；明确厂商扩展和未知引用。
3. **集成缺口解释**：扩展应用实例/组合、OS/RTE 调度、模式管理和工具日志关联，分别呈现历史工具失败、当前结构事实和待厂商验证项。
4. **两版配置影响**：对比两个导出快照，追踪 PDU/信号/任务绑定变化；需要实际工具校验/生成时，另行绑定合法环境及执行证据。

## 本轮范围

新增 `inspect-ecuc-project`、`verify-ecuc-inspection` 和 `ecuc-project-inspection-0.1` 闭合 schema，实现第 1 项。输出为受限结构报告，所有发现等级为 WARNING，不擅自替代厂商生成错误等级。状态 `no-issues-in-scope` 仅表示已实现检查未发现问题，不代表工程可生成、可编译或可运行。

输入限 UTF-8、r4.0 namespace，保留实际 schemaLocation，不将版本标签强制归一。每文件最多 64 MiB，总输入最多 256 MiB；不执行 DTD、实体或工具，输入引用须位于 DPA 目录内。外部系统/BSW 定义、参数取值约束和 INSTANCE-REFERENCE 不在首轮解析范围。没有工具安装/许可或现场执行证据时，不声称商业工具往返已恢复。

本地工程和其来源快照只保存在忽略目录，不提交到公共 Git/CI；公开测试使用手工构造的最小合成工程。

## 回归口径

新增运行源码与 CLI 后，P24 历史冻结不再适用于当前源码。原负例清单/hash 和历史验收保持；严格 `--held-out` 仍检查原冻结并在变更后拒绝。当前 CI 显式使用 `--historical-regression`，输出版本 0.2、独立历史回归字段、`freeze_verified: false` 和当前 runtime hash，不能将其称为新增独立负例或重新冻结验收。

# P27 声明式 ECUC 配置变更验收（implementing）

P26 受限静态审查阶段验收后进入本阶段。目标用户能力是：工程人员在同一个项目配置中声明基线/候选 ECUC 输入、所需检查和接受条件，一次运行产生可重放的变更验收与交付包，无需手工拼接多个命令。

## 实施顺序与阶段门

1. 复用 P26 引擎并接入现有项目编排，显式版本化项目配置；保留旧 0.1–0.5 项目兼容。规则与比较实现不另写一份。
2. 至少两个结构不同的公开合成 ECUC 工程使用同一声明流程，加入第二个工程不改运行内核；覆盖配置健康、任务缺口、通信退化、范围未知、来源被篡改。
3. 声明门按 evidence 区分 passed/failed/unassessed/blocked，不将缺少应用输入、未知厂商字段或历史日志当自动通过/当前故障；非法配置在执行前拒绝。
4. 接入项目报告、比较和审查交付入口，让变更对象与受影响验收项可追踪；工程报告的 before/after 来源、配置策略和运行版本须可离线复验。
5. 安装后的 CLI 在仓库外重跑两项目及故障；Windows/Ubuntu 七 job、完整归档与迁移复验；更新使用手册和独立学习练习。

第一项任务：冻结新项目版本的 ECUC 输入、基线选择及检查声明契约，完成一个正常/一个缺口阻止接受的端到端路径，再加入第二项目验证抽象。

## 范围边界

只保留一个主实现阶段。P26 保持已验收消费者，P25 人工演示/外部反馈独立待取得。P22 商业工具往返、ECU 实时调度、实际厂商生成及物理 ECU 仍需另行真实环境证据。本阶段不自建配置生成器、不自动联系外部人员、不引入远程服务或扩大协议范围。

## 本轮实现（2026-10-02）

已实现 0.6 项目、五检查四状态、两种公开工程、审查/比较及原输入移除后的复验；旧项目兼容。当前最终本地与远端验收进行中，见[验收表](p27-acceptance.md)和[指南](p27-ecuc-acceptance-guide.md)。阶段通过后下一项为[P28 对象级配置变更验收策略](p28-object-acceptance-plan.md)。
